# 앨범 공통화·원본 자동 변환

- 작성일: 2026-08-31
- 상태: **3단계 — 두 앨범의 공통 3D 엔진·무대 적용. 원본 변환 도구와 전체 성능 최적화는 미구현.**
- 최초 분석 코드 기준: `41d082b0178a89088aff7cb1bb84cf3cfa8a9e7b`. 1단계 문서 체크포인트: `7bab6df`.
- 범위: 기존 기능 보존, 공통 UI/3D 경계, 원본 입력 규격과 변환 검증.
- 현재 운영 안내: [ALBUM-WORKFLOW.md](../ALBUM-WORKFLOW.md). 현재 타입의 구현 상태와 아래의 목표 구조를 혼동하지 않는다.

## 1. 결정 사항과 미확정 사항

### 사용자 확정

1. 모든 앨범은 위치·UI·애니메이션·3D 조작의 공통 규칙을 사용한다. 앨범 고유 디자인과 실제 패키지 차이는 보존한다.
2. 새 앨범은 사용자가 면별로 자르지 않은 원본 묶음으로 받는다. 기존에 잘라진 한범수류·지영희류 자산도 계속 사용할 수 있어야 한다.
3. 평조회상 CD 라벨은 제공된 **바깥 원을 외곽, 안쪽 원을 중앙 제외 영역**으로 사용한다. 이 결정은 라벨 영역에 대한 것으로, 다른 앨범의 CD나 별도 제조 치수를 임의로 바꾸는 근거가 아니다.
4. 속지 1번의 왼쪽 면은 **접착면**이다. 읽는 페이지에서 제외한다. 오른쪽은 북클릿 앞표지로 취급한다.
5. 칼선 파일은 좌표 확인용, 선 없는 원본은 실제 표면용이다. 선을 지우거나 디자인을 생성형 도구로 다시 그리지 않는다.
6. 기존 기능을 유지하면서 교체된 구형 코드·분기·CSS·임시 파일은 같은 작업 단위에서 제거한다. CSS 끝에 재정의를 누적하지 않는다.
7. 작업을 단계별로 보고하고 다음 단계 승인 전에 확장하지 않는다. 1단계는 설계·기준선, 2단계는 공통 DOM UI·CSS, 승인된 3단계는 공통 3D 무대와 CD 복귀를 다룬다. 원본 변환·업로더·음원 로직·공개 배포는 3단계에서 제외한다.

### 확정 전 자동 발행 금지

| 항목 | 현재 상태 | 필요한 확인 |
| --- | --- | --- |
| 평조회상 북클릿 읽는 순서 | 미확정 | 파일 번호가 인쇄 배치인지 읽는 순서인지 확인. 접착면 제외 뒤 각 면의 순서 승인 |
| 디지팩 면 배정·접힌 방향 | 미확정 | 전개도의 위·아래 면을 실제 내부/외부에 배정하고 회전 방향 확인 |
| 물성 | 미확정 | 종이·트레이·CD 두께/재질은 별도 프로필. 디자인에 찍힌 질감을 실제 양각으로 추정하지 않음 |
| 새 앨범 ID·발매일·음원·최종 문구 | 미확정 | 파일에서 보이는 문구나 OCR을 운영 데이터의 확정값으로 자동 채택하지 않음 |
| 관리자 업로드 화면 | 별도 범위 | 우선 로컬 일괄 등록 도구를 설계. 웹 업로더·인증·저장소·서버 작업은 별도 승인 |

이미지 분할·미리보기까지는 미확정 항목을 표시하며 진행할 수 있지만, 페이지 구성과 면 배정이 미확정인 앨범은 공개용 manifest를 발행하지 않는다. 이 보류는 기존 두 앨범의 UI 공통화를 막지 않는다.

## 2. 원본 인벤토리와 규격 초안

사용자가 제공한 평조회상 폴더의 `PNG최종/`와 `홈페이지용/`를 각각 artwork/guide로 읽었다. 원본은 외부 보관 위치에 그대로 두며 저장소·public에 복사하지 않았다. 로컬 절대경로는 공개 manifest에 넣지 않는다.

| source ID | 양쪽 폴더에서 대응하는 파일명 | 크기 | 확인 |
| --- | --- | --- | --- |
| `booklet-1` … `booklet-6` | `CP_디지팩(소형) 속지 칼선_130_120_1.png` … `_6.png` | 각 3508×2481 | 6쌍 모두 동일 캔버스, RGB |
| `disc-label` | `CD DVD라벨 칼선.png` | 1418×1418 | 동일 캔버스, RGB, 투명 채널 없음 |
| `package-sheet` | `CP_디지팩(소형) _ 2단_속지부착.png` | 4725×4725 | 동일 캔버스, RGB |

- artwork 합계: 50,717,261 bytes. guide 합계: 50,803,771 bytes.
- 재현용 묶음 SHA-256: artwork `66ecd5c6140fa981205fe9b7a333c97b2f6d564f1880d63cc39d377b0e39de8d`, guide `b4d2452b0d96db7db7f67ca857ce9fa2cc8a89bb4799e8046ca02660d38b5bce`.
- 묶음 해시 방법: 위 표의 속지 1~6, CD, 전개도 순서로 각 파일을 SHA-256 처리하고, ASCII 순번(1~8) + NUL + 해당 32-byte digest를 이어 붙여 SHA-256. 입력 파일 내용 변화 확인용이며 런타임 캐시 키는 아니다.
- 이전 칼선 분석에서 300dpi 메타데이터와 선 중심 간격으로 환산한 값: 속지 한 면 약 130×120mm, 패키지 한 면 약 141×125mm, 책등 약 7mm. 제조사 치수 검증 완료값이 아니다.

### 좌표 규칙

원본 좌상단 원점, x는 오른쪽, y는 아래쪽. 아래는 2026-08-31 PNG 분석의 **초기 보정 후보**다. 분홍선의 두께와 안티앨리어싱 때문에 최종 정수 crop 경계로 바로 사용하지 않는다.

| 원본 | 선 중심/영역 후보 (원본 px) |
| --- | --- |
| 속지 6장 공통 | 세로선 x≈318 / 1853.5 / 3389, 가로선 y≈373.5 / 1791.5 |
| 전개도 | 세로선 x≈647.5 / 2313 / 2395.5 / 4061, 가로선 y≈802.5 / 2279 / 3755.5 |
| CD 라벨 | 중심≈(710,713), 바깥 반지름≈692px, 안쪽 반지름≈136px |

1. 재단 영역과 도련을 구분하고 분할 경계가 이어지는지 미리보기로 확인한다. 접착면·무문자 디자인을 배경색 기반 자동 trim으로 삭제하지 않는다.
2. 먼저 원본 해상도에서 면을 나누고, 회전·방향을 보정한 뒤 최종 용도 크기로 줄인다. 전개도 전체를 먼저 줄이지 않는다.
3. crop은 최종 구현에서 `[left, top, right, bottom)` 반열린 경계로 정의한다. 같은 경계의 반올림 정책을 공유해 틈·중복을 방지한다.
4. CD는 정사각형 artwork를 그대로 입력받아 승인된 원형 영역을 사용한다. 외곽/중앙의 검은 테두리와 투명 영역 오처리 여부를 확대 검수한다.
5. 캔버스 크기가 같다는 이유만으로 정렬까지 보장하지 않는다. 원본 위치가 달라지면 등록된 템플릿을 재보정한다. 크기·해시 변화 시 경고하고 자동 발행하지 않는다.
6. 6개의 펼침면을 12개 후보 면으로 나누고 접착면 하나를 제외하면 11개 표시 후보가 생긴다. 이를 곧바로 승인된 11페이지 읽기 순서로 간주하지 않는다.

## 3. 공통 입력 구조 — 설계 계약

아래 이름은 목표 책임을 설명하는 설계명이다. 지금 빈 타입 파일·임시 컴포넌트를 만들거나 `albums.ts`를 중복 데이터 파일로 복사하지 않는다.

### 입력 → 변환 → 표시의 경계

| 계층 | 소유하는 정보 | 소유하지 않는 정보 |
| --- | --- | --- |
| 기존 `Album` | 앨범 ID, 문구, 트랙·음원, 크레딧, 링크 | PNG 재단 좌표, GPU 객체 |
| `AlbumSource` | 입력 파일 참조, 원본 해시, 승인 상태, 면 배정·읽는 순서 | 페이지 UI 좌표·카메라 |
| `PackagingTemplate` | 규격별 캔버스·재단 영역·접착면·접힘·UV 방향·라벨 영역 | 특정 앨범 제목이나 CSS 클래스 |
| `AlbumAssetManifest` | 검증된 웹 이미지 경로·치수·순서·생성 출처·형식 버전 | 로컬 경로, 칼선 이미지, 미승인 배정 |
| `AlbumPresentation` | 공통 엔진이 읽을 manifest 참조, 재질 프로필, 앨범 테마 | 앨범 ID별 복제 UI·상태 머신 |

`Album`의 현재 `coverImage`, `cdLabelImage`, `booklet.previewImages`, `albumHero`, `detailExperience` 소비 지점을 단계별로 이 계약에 연결한다. 이행 기간에도 값은 한 곳에서 파생하며 수동으로 두 군데 유지하지 않는다. 전환 완료 시 사용하지 않는 옛 필드/adapter/분기를 제거한다.

### 두 입력 모드, 하나의 출력 계약

| 항목 | `prepared-assets` — 기존 잘라진 이미지 | `print-layout` — 새 원본 묶음 |
| --- | --- | --- |
| 공통 | `schemaVersion`, `albumId`, 명시적 입력 mode, 승인 정보 | 동일 |
| 파일 입력 | front/back/spine/interior/CD 경로와 정렬된 booklet 목록 | source ID → artwork + 선택적 guide + 각 파일 해시 |
| 규격 | 기존 패키지 치수·재질 프로필 보존 | `templateId` + `templateVersion` + 원본 캔버스 검증 |
| 면 연결 | 이미 분리된 면의 역할 확인 | `faceMap`: source ID + region ID + 회전/뒤집기 |
| 북클릿 | 기존 등록 순서 보존 | `bookletSequence`: 승인된 region 참조 목록. 미확정이면 `null` |
| 출력 | 동일한 `AlbumAssetManifest` | 동일한 `AlbumAssetManifest` |

`region ID`는 `booklet-1.left`, `booklet-1.right`처럼 원본의 기하학적 면을 식별한다. `page-01` 같은 읽는 순서와 구분한다. `booklet-1.left`의 role은 `adhesive`, `includeInReader=false`로 고정한다. 재질·입력 유형과 앨범 테마를 서로 다른 enum/설정으로 두어 새 앨범 ID마다 엔진 분기를 늘리지 않는다.

### manifest에 필요한 최소 데이터

- `schemaVersion`, `albumId`, 원본/템플릿/변환기 버전 식별 정보.
- 면별 이미지의 `src`, `width`, `height`, `alt` 또는 장식용 여부, 재질 프로필 참조.
- CD 라벨의 외곽/중앙 제외 영역, 3D 실물 형상 프로필과의 대응 정보.
- `booklet.cover`와 순서가 확정된 `booklet.pages[]`; 각 페이지의 안정적인 ID·방향·원본 region 참조.
- desktop/mobile 배경은 별도 자산 참조. 전개도에서 임의의 배경을 생성하지 않는다.
- PDF·음원은 기존 `Album`의 실제 등록값을 사용. 이미지에서 자동 생성·추정하지 않는다.

처음에는 WebP 등 현재 런타임 형식을 유지하되 작은 인쇄 글자·CD 경계의 화질 검수를 통과해야 한다. 모든 표면을 일괄 같은 해상도·압축률로 만들지 않는다. 대용량 원본·guide·PDF를 초기 3D 텍스처로 로드하지 않는다.

## 4. 변환·발행 검증

1. 입력 검사: 파일 형식·실제 디코딩·픽셀 수/용량 제한·파일 누락·해시·캔버스 크기를 검사한다. 추후 ZIP 입력을 추가하면 경로 탈출·압축 해제 용량 제한도 필요하다.
2. 규격 검사: 모든 region이 캔버스 안에 있고 면적이 양수인지, CD 중심/반지름이 유효한지, 회전·반전·도련 정책이 명시되어 있는지 검사한다.
3. 의미 검사: 접착면이 읽는 목록에 들어가지 않는지, 표지가 중복되지 않는지, 예상 면의 누락/중복과 미승인 순서·면 배정이 없는지 검사한다.
4. 원본 보존: 읽기 전용으로 사용하며 웹용 생성 결과는 분리한다. 동일 입력+변환기+규격 버전에서 동일한 결과를 재현할 수 있어야 한다.
5. 미리보기: 분할 면과 열린/닫힌 패키지, 책등 방향, 북클릿 순서, CD 외곽·중앙을 확인한다. 픽셀 테스트와 사람의 내용 확인을 구분한다.
6. 발행: 모든 검증을 통과한 산출물과 manifest를 함께 활성화한다. 실패·취소 시 현재 공개 앨범은 유지한다. 오래된 비동기 변환 결과가 최신 입력을 덮어쓰지 않도록 작업 버전을 검사한다.
7. 정리: 작업 소유 임시 파일·실패 산출물·참조가 끊긴 생성물만 정확한 경로로 정리한다. 이전 공개본은 새 결과 활성화·회귀 확인 전에 삭제하지 않는다. 필요한 원본/활성 캐시는 찌꺼기로 취급하지 않는다.

## 5. 공통 UI·3D와 보존할 기능

- 화면 배치의 소유자는 공통 레이아웃이다. 패키지와 DOM 정보가 같은 안전 영역·기준선을 사용한다. 앨범별 배경 anchor는 레이아웃 규칙을 우회하는 자유 좌표가 아니다.
- HOME 제목과 패키지 사이 여유, 상세 정보·크레딧 중앙 정렬, 열린 패키지 아래 BOOKLET/TRACKS 배치를 공통 규칙으로 만든다. 연결선의 SVG·CSS·애니메이션은 교체 시 삭제한다.
- 카메라·화면상 크기·상태별 목표 위치·드래그/관성·모션 시간·품질 정책은 공통. 실제 종이/플라스틱 형상과 디자인은 프로필/자산으로 보존한다.
- 앞·뒤·책등은 외장 수명에 속한다. 내부 선로딩 여부 때문에 뒷표지가 사라지지 않아야 한다.
- 안정 상태는 `CLOSED / ALBUM_OPEN / BOOKLET_FOCUS / PLAYER_FOCUS`; 전환은 별도의 from/to/phase와 작업 ID로 관리한다. UI 활성화는 실제 settle 이후, 오류·취소에도 잠금이 풀려야 한다.
- CD 복귀는 현재 world 위치·회전·크기를 보존하며 트레이의 목표 자세까지 보간한다. 3단계에서는 Scene 부모를 유지해 재결합 자체를 없앴다. 모드 변경만으로 package를 순간 표시하거나 quaternion/scale을 강제로 초기화하지 않는다.
- 공통 Canvas 수명과 텍스처 캐시 소유자를 정한다. 단일 공통 무대를 목표로 하되 모든 앨범을 계속 렌더링하는 방식은 금지한다. 정지 상태의 연산을 멈추고 회전·관성·전환 중에는 렌더를 유지한다.

## 9. 3단계 — 공통 3D 무대·CD 복귀 (2026-08-31)

### 구현과 책임

- `AlbumStages.tsx`: 기존 앨범별 persistent provider 두 개를 하나의 구현으로 교체했다. `detailExperience`가 있는 앨범을 등록하고, 활성화/미리 준비 중인 무대만 렌더링한다. 같은 앨범의 HOME→상세는 Canvas와 패키지를 유지한다. **전 사이트 단일 Canvas로 바꾼 것은 아니다.** 다른 앨범을 준비하는 동안에는 두 Canvas가 존재할 수 있다.
- `AlbumDetailExperience3D.tsx`: 두 앨범이 카메라, 조명, 화면별 위치·크기, hinge, CD, 북클릿과 조작 규칙을 함께 사용한다. 카메라 FOV 42, desktop CLOSED 중심은 화면 너비의 37%, scale 1.18, OPEN scale 1.08이다. 모바일은 viewport에 비례한 공통 배치를 사용한다.
- `packageProfile.ts`: 실제 표지/책등 비율과 종이·스캔 패키지 재질 차이만 분리한다. 현재는 기존 theme 값에서 프로필을 선택하는 호환 경계다. 별도의 새 manifest 입력 체계가 구현된 것은 아니다.
- `PackageMaterials.tsx`: 인쇄면·종이 가장자리·플라스틱 공통 재질. 이전 앨범별 재질 파일 두 개와 한범수류 전용 3D engine, 앨범별 stage 파일·CSS를 제거했다. 삭제 전 파일은 Git에서 복구할 수 있다.
- `DiscMotion`: CD의 부모를 Scene으로 고정한다. 트레이의 world 위치·회전·크기를 읽어 보간하며, 위치뿐 아니라 회전과 scale의 오차도 복귀 완료 조건에 포함한다. 부모 패키지의 frame 업데이트를 먼저 실행한다.
- `PackageFade`: 외장 재질만 한 번 수집해 opacity를 보간한다. PLAYER 전환 때 package 전체를 즉시 `visible=false/true`로 바꾸던 코드를 제거했다. CD 라벨은 이동 중 앞쪽 표시 순서를 사용하고, 트레이에 안착하면 물리적 깊이 검사를 복원한다.
- 새 경로에서 읽지 않는 회전 sessionStorage 저장/조회와 매 프레임 저장, 중복 ResizeObserver·미사용 props를 제거했다. 일반 앨범용 기존 HOME fallback 자체는 아직 쓰일 수 있어 유지했다.
- 두 detail controller와 플레이어 DOM·키보드/터치 handler·`useAlbumAudio`는 보존했다. 따라서 모든 UI/controller 중복 제거까지 완료된 상태로 표현하지 않는다.

### 결함별 변경

| 항목 | 확인한 원인 | 3단계 변경 |
| --- | --- | --- |
| 지영희류 뒷표지 | 외장 back이 내부 texture 로딩에 종속 | 앞·뒤·책등은 항상 외장으로 렌더링 |
| 한범수류 CD 검은 가장자리/중앙 | RGBA 스캔을 불투명 circle로 표시 | 기존 RGBA 라벨의 알파 적용, MSAA alpha-to-coverage, 스캔 외곽/중앙에 맞는 ring 기판 |
| CD→앨범 복귀 | 부모 attach 변경과 위치만의 완료 판정, 회전/크기 강제 초기화, package 즉시 표시 | Scene 부모 고정, 전체 transform 보간, 외장 fade와 라벨 전환 순서 |
| GPU 준비 | frame 중 동기 compile | 비동기 compileAsync로 이동; stage 준비에는 8초 fallback을 두고 실패 시에도 이동 허용 |
| CLOSE→HOME 내부 수명 | 로딩 flag 변경 시 dispose된 내부 texture를 state가 계속 참조 | 내부를 한 번 요청하면 같은 Scene의 수명 동안 보유 |

원본 PNG/WebP·칼선·앨범 데이터·음원·의존성은 변경하지 않았다. 한범수류 원본 alpha 중앙 행에서 유효 외곽 약 0.981R, 안쪽 약 0.133R을 확인해 기판에 사용했다. 이는 스캔 대응값이며 평조회상 라벨 칼선 규격으로 재사용하지 않는다.

재질 설정 참고: [Three.js Material](https://threejs.org/docs/pages/Material.html). 좌표계 참고: [Three.js Object3D](https://threejs.org/docs/pages/Object3D.html). API 설명과 실제 브라우저 검증 결과를 구분한다.

### 검증

- `npm run lint`, `npm run build` 통과. 약 884KB 공유 3D chunk 경고는 남아 있다. bundle 파일 크기는 FPS나 최초 방문 전송량 측정값이 아니다.
- `node --test scripts/test-album-motion.mjs`: 6개 통과. world transform 대응, 회전/scale을 포함한 완료 판정, 중간 방향 반전의 연속성, 안착 후 트레이의 급격한 이동을 지연 없이 추종하는지, reduced-motion 한 단계 정착, 외장 opacity·depthWrite 보존을 검사한다. Node 24.15.0에서 실행했으며 브라우저 전체 기능 테스트와 구분한다.
- 내부 브라우저의 로컬 production preview, 1444×986: 두 앨범 OPEN·TRACKS·BACK·BOOKLET 진입, 지영희류 P2–P3→P4–P5→P6–P7 끝 경계·PREVIOUS·BACK·CLOSE, 06 선택·12:06 표시 확인.
- 한범수류 P2–P3부터 P10–P11까지 NEXT 4회, 마지막 NEXT 비활성, PREVIOUS·BACK·CLOSE 확인. 최종 빌드에서 CD 확대 화면의 외곽/중앙 투명 영역과 복귀 중 라벨이 북클릿에 잘리지 않는 장면을 캡처했다.
- HOME 새 진입 후 RECENT WORKS에서 지영희류를 선택하고 내부를 열지 않은 상태의 뒷표지 인쇄면을 확인했다. VIEW ALBUM→열린 상세와 NEXT ALBUM 양방향 이동도 확인했다.
- 한범수류 실제 등록 06 트랙의 PLAY→PAUSE와 시간 진행(0:34/13:57)을 확인했다. 소리 청취·전체 12트랙·seek/volume 성공으로 확대 해석하지 않는다.
- 모바일 실기기·touch/키보드·브라우저 reduced-motion·WebGL 실패·느린 네트워크·FPS/long task는 이번 단계 미검증이다. 단위 테스트의 reduced-motion 확인이 브라우저 검수를 대신하지 않는다.

### 다음 단계와 남은 한계

- 원본 변환 도구·면 매핑 승인·신규 앨범 등록은 아직 시작하지 않았다. 평조회상 CD 칼선 기준과 접착면 제외 계약은 그대로 유지한다.
- 일반 페이지 전환, 초기 texture decode/upload, 캐시 정책과 비활성 frame 연산은 별도 계측·개선이 필요하다. 이 단계로 전체 stutter가 해소됐다고 주장하지 않는다.
- 북클릿 내부의 frame별 임시 객체/재질 순회, 자산 로딩 실패의 사용자 안내 등은 아직 남아 있다. stage prewarm timeout은 모든 다운로드·모든 오류를 처리하는 전역 보장값이 아니다.
- 시작 전부터 변경돼 있던 운영 Markdown 16개는 이번 소스 체크포인트에 섞지 않고 보존한다. 운영 문서의 이전 engine 이름·배경 anchor 기준 설명보다 이 절의 최신 코드 책임을 우선한다. 그 문서들의 기존 수정분과 충돌하지 않는 통합 정리는 별도 검토가 필요하다.
